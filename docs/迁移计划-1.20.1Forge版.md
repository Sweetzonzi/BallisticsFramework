# BallisticsFramework 多版本迁移计划：1.20.1 Forge 版

> 本文档供开发者或自动化 Agent 按步骤完成从 NeoForge 1.21.1 到 Forge 1.20.1 的移植。
> 当前版本基线：v1.0.0.alpha.3（NeoForge 1.21.1 + Java 21）
> 目标版本：Forge 1.20.1 + Java 17

***

## 〇、前置评估：哪些代码需要改？

在动手前理解工作量——BallisticsFramework 作为一个纯 logic library，**绝大多数代码天然跨版本兼容**：

| 类别                                           | 文件数   | 改动量                                          |
| -------------------------------------------- | ----- | -------------------------------------------- |
| 纯业务逻辑（零 Minecraft 依赖）                        | 6 个   | **零改动，直接复制**                                 |
| 仅依赖跨版本稳定 API（Entity / DamageSource / Vec3 等） | 9 个   | **零改动，直接复制**                                 |
| 涉及 Mod 加载入口 / 构建配置                           | \~6 个 | **需要重写或修改**                                  |
| Mixin 注入                                     | 2 个   | **零改动**——`hurt(DamageSource, float)` 签名跨版本一致 |

**底线**：Java 源码中仅 `BallisticsFramework.java` 的 **1 行 import** 需要改。

***

## 一、分支策略

使用**多分支策略**，每个 Minecraft 版本一个独立 Git 分支：

```
main (1.21.1-neoforge)     ← 当前主线
├── 1.20.1-forge            ← 本次新建
├── 26.1.2-neoforge           ← 未来(Minecraft版本号格式更新后的新版本)
└── ...
```

### 工作流规则

| 场景         | 操作                                                            |
| ---------- | ------------------------------------------------------------- |
| 新增 API 功能  | 在 `main` 开发 → `git cherry-pick` 到 `1.20.1-forge`              |
| 单版本 bugfix | 直接在对应分支开发并提交                                                  |
| 跨版本 bugfix | 在 `main` 修复 → `cherry-pick` 到所有活跃分支                           |
| 发布         | 各分支独立 tag（如 `v1.0.0+1.21.1-neoforge` / `v1.0.0+1.20.1-forge`） |

#### 3.3 `neoForge {}` 替换为 `minecraft {}`

```groovy
// 替换前（NeoForge 完整 DSL）
neoForge {
    version = project.neo_version
    runs {
        client {
            client()
            systemProperty 'neoforge.enabledGameTestNamespaces', project.mod_id
        }
        server {
            server()
            programArgument '--nogui'
            systemProperty 'neoforge.enabledGameTestNamespaces', project.mod_id
        }
        gameTestServer {
            type = "gameTestServer"
            systemProperty 'neoforge.enabledGameTestNamespaces', project.mod_id
        }
        data {
            data()
            programArguments.addAll '--mod', project.mod_id, '--all',
                    '--output', file('src/generated/resources/').getAbsolutePath(),
                    '--existing', file('src/main/resources/').getAbsolutePath()
        }
        configureEach {
            systemProperty 'forge.logging.markers', 'REGISTRIES'
            logLevel = org.slf4j.event.Level.DEBUG
        }
    }
    mods {
        "${mod_id}" {
            sourceSet(sourceSets.main)
        }
    }
}

// 替换后（ForgeGradle DSL）
minecraft {
    mappings channel: 'official', version: '1.20.1'

    runs {
        client {
            workingDirectory project.file('run')
            property 'forge.logging.markers', 'REGISTRIES'
            property 'forge.logging.console.level', 'debug'
            mods {
                "${mod_id}" {
                    source sourceSets.main
                }
            }
        }

        server {
            workingDirectory project.file('run')
            property 'forge.logging.markers', 'REGISTRIES'
            property 'forge.logging.console.level', 'debug'
            mods {
                "${mod_id}" {
                    source sourceSets.main
                }
            }
        }

            workingDirectory project.file('run')

            property 'forge.logging.console.level', 'debug'

                    '--output', file('src/generated/resources/'),
                    '--existing', file('src/main/resources/')
            mods {
                "${mod_id}" {
                    source sourceSets.main
                }
            }
        }
    }
}
```

#### 3.5 generateModMetadata 的模板路径

由于 Forge 使用 `mods.toml` 而非 `neoforge.mods.toml`，需要确保模板文件路径正确：

```groovy
var generateModMetadata = tasks.register("generateModMetadata", ProcessResources) {
    var replaceProperties = [
            minecraft_version      : minecraft_version,
            minecraft_version_range: minecraft_version_range,
            forge_version          : forge_version,
            forge_version_range    : forge_version_range,
            loader_version_range   : loader_version_range,
            mod_id                 : mod_id,
            mod_name               : mod_name,
            mod_license            : mod_license,
            mod_version            : mod_version,
            mod_authors            : mod_authors,
            mod_description        : mod_description
    ]
    inputs.properties replaceProperties
    expand replaceProperties
    from "src/main/templates"  // 保持此路径不变，但模板文件需重命名
    into "build/generated/sources/modMetadata"
}
```

> 但要移除末尾的 `neoForge.ideSyncTask generateModMetadata`——ForgeGradle 使用不同的同步机制。

```groovy
// 删除此行
neoForge.ideSyncTask generateModMetadata

// 改为 ForgeGradle 等效配置（如需）：
// 通常不需要——ForgeGradle 会自动处理 IDE 同步
```

### 步骤 5：创建 Forge 版 mods.toml

### 3.2 关于 EquipmentSlot 的注意事项

1.20.1 的 `EquipmentSlot` 是一个**枚举**（`enum`），1.21.1 也是枚举。区别在于：

- 1.20.1：`HEAD`, `CHEST`, `LEGS`, `FEET`, `MAINHAND`, `OFFHAND`（共 6 个）
- 1.21.1：增加了 `BODY`（共 7 个）

BallisticsFramework 当前只使用 `HEAD`/`CHEST`/`LEGS`/`FEET` 四个护甲槽位，不受影响。
适配器 [BFArmorAdapter.java](file:///d:/Files/Project_MinecraftMods/BallisticsFramework/src/main/java/io/github/sweetzonzi/ballistics_framework/internal/BFArmorAdapter.java#L21-L26) 中 `ARMOR_SLOTS` 数组不包含 `BODY`，移植到 1.20.1 完全兼容。

### 3.3 关于 Mixin 注入点

`Entity#hurt(DamageSource, float)` 和 `LivingEntity#hurt(DamageSource, float)` 的签名在 1.20.1 和 1.21.1 之间**完全相同**：

- 方法名：`hurt`
- 参数类型：`DamageSource, float`
- 返回类型：`boolean`
- 注入点：`HEAD` + `cancellable = true`

因此两个 Mixin 文件可以直接复制到 1.20.1 使用，无需修改。

### 3.4 关于语言文件

`src/main/resources/assets/ballistics_framework/lang/en_us.json` 和 `zh_cn.json` 直接复制，无需修改。

## 四、常见问题排查

### Q1：编译报错——找不到 `net.neoforged` 包

```
error: package net.neoforged.fml.common does not exist
```

**原因**：`BallisticsFramework.java` 的 import 还是 NeoForge 的。
**修复**：确认已执行 [步骤 6](#步骤-6修改-ballisticsframeworkjava主类)。

### Q2：`./gradlew build` 找不到 ForgeGradle 插件

```
Plugin with id 'net.minecraftforge.gradle' not found.
```

**原因**：`settings.gradle` 的 `pluginManagement` 中 Maven 仓库漏配。
**修复**：确认已执行 [步骤 4](#步骤-4修改-settingsgradle)，添加了 `https://maven.minecraftforge.net/`。

### Q3：运行时 Mixin 注入失败——compatibilityLevel 不匹配

```
Mixin compatibility level JAVA_21 is not supported by the current mixin version
```

**原因**：`mixins.json` 中的 `compatibilityLevel` 为 `JAVA_21`，但 1.20.1 使用 Java 17。
**修复**：确认已执行 [步骤 7](#步骤-7修改-mixinsjson-的兼容级别)，改为 `JAVA_17`。

### Q4：模组加载时报错——依赖版本不满足

```
Mod 'ballistics_framework' requires version [21,) of 'neoforge'
```

**原因**：`mods.toml` 的 `dependencies` 中还在声明对 `neoforge` 的依赖。
**修复**：确认已执行 [步骤 5](#步骤-5创建-forge-版-modstoml)，改为 `forge` 并使用 `${forge_version_range}`。

### Q5：原版伤害拦截异常或崩溃

**排查思路**：

1. 确认 Mixin 已正确加载——在日志中搜索 `Mixin` 关键字
2. 确认 `BFHurtInterceptor` 的四种分支判断逻辑是否进入预期分支
3. 确认实体穿戴的护甲物品是否正确实现了 `BFArmorMaterial`

### Q6：runClient / runServer 启动时崩溃

```
java.lang.NoClassDefFoundError: net/neoforged/...
java.lang.ClassNotFoundException: net.neoforged.fml.common.Mod
```

**原因**：`BallisticsFramework.java` 的 import 仍是 NeoForge 版（`net.neoforged`）。
**修复**：确认已执行 [步骤 6](#步骤-6修改-ballisticsframeworkjava主类)。

### Q7：GameTest 全部失败或找不到测试

```
No tests found matching ...
```

**原因**：Forge 和 NeoForge 的 GameTest 注解（`@GameTestHolder`、`@PrefixGameTestTemplate`）位于不同包，且 `runGameTestServer` task 名称可能不同。
**修复**：

- 将 `@GameTestHolder("ballistics_framework")` 的 import 从 `net.neoforged.neoforge.gametest.GameTestHolder` 改为 `net.minecraftforge.gametest.GameTestHolder`（如 Forge 有此注解）
- 如果 Forge 1.20.1 不提供 `@PrefixGameTestTemplate`，删除该注解，测试模板由 `template` 属性指定完整路径
- 确认 `runGameTestServer` task 在 ForgeGradle 中的名称（可能为 `test` 或需自定义）

### Q8：Config 文件未生成

```
Could not find file: run/defaultconfigs/ballistics_framework-common.toml
```

**原因**：Forge 的 Config 注册方式与 NeoForge 不同。
**修复**：在 `BallisticsFramework` 构造器中，将：

```java
// NeoForge 方式（当前代码）
modContainer.registerConfig(ModConfig.Type.COMMON, SPEC);

// 改为 Forge 方式
ModLoadingContext.get().registerConfig(ModConfig.Type.COMMON, SPEC);
```

注意 `ModLoadingContext` 在 Forge 包为 `net.minecraftforge.fml.config.ModLoadingContext`，`ModConfig` 为 `net.minecraftforge.fml.config.ModConfig`。

### Q9：runClient 中示例物品不可见

**排查思路**：

1. 确认 `run/defaultconfigs/ballistics_framework-common.toml` 中 `enableExampleContent` 为 `true`
2. 检查客户端日志是否有 `[BF-Example]` 相关的注册成功的输出
3. 确认 `ExampleClientEvents` 中 `@EventBusSubscriber` 的 `value = Dist.CLIENT` 的包在 Forge 下是否兼容（NeoForge: `net.neoforged.api.distmarker.Dist`；Forge: `net.minecraftforge.api.distmarker.Dist`——虽然类名相同，但确认包路径）

## 五、维护建议

### 5.1 保持 API 层的版本无关性

继续坚持以下原则，让未来的跨版本迁移保持低成本：

- 纯数据类（枚举、record）不引入 Minecraft 依赖
- 接口方法参数使用跨版本稳定的 API 类
- Mixin 注入点优先使用 `HEAD` + `cancellable` 模式，避免 `MODIFY` 或 `REDIRECT`

### 5.2 分支同步节奏

| 频率               | 操作                                |
| ---------------- | --------------------------------- |
| 每次 `main` 新增 API | 立即 `cherry-pick` 到 `1.20.1-forge` |
| 每次发布前            | 确保所有活跃分支构建通过                      |
| 每季度              | 检查各分支依赖版本是否为最新 patch              |

### 5.3 未来支持更多版本

新增版本分支的迁移工作量预估（基于本项目的代码特征）：

| 目标               | Java 版本 | 需改文件数            | 预计工时     |
| ---------------- | ------- | ---------------- | -------- |
| 1.20.1 Forge（本次） | 17      | \~6 个（含配置）       | 1-2 小时   |
| 1.22 NeoForge    | 21+     | \~3 个（主要配置）      | 0.5-1 小时 |
| 1.19.2 Forge     | 17      | \~7 个（Mixin 需验证） | 2-3 小时   |

### 6.2 注册基础设施差异对照

#### `DeferredRegister` 包路径

```java
// NeoForge 1.21.1
import net.neoforged.neoforge.registries.DeferredRegister;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredItem;

// Forge 1.20.1
import net.minecraftforge.registries.DeferredRegister;
import net.minecraftforge.registries.RegistryObject;  // 对应 DeferredHolder
// 注意：Forge 没有 DeferredItem，需要用 RegistryObject<Item> 替代
```

在 `ExampleContent.java` 中，`DeferredItem<ExampleArmorItem>` 需改为 `RegistryObject<ExampleArmorItem>`。

#### `BallisticsFramework.java` 构造器签名

```java
// NeoForge 1.21.1（当前代码）
public BallisticsFramework(IEventBus modEventBus, ModContainer modContainer)

// Forge 1.20.1
public BallisticsFramework()
// 或使用 FMLJavaModLoadingContext 获取 IEventBus
```

修正方式：

- 删除构造器参数，在构造器内部通过 `FMLJavaModLoadingContext.get().getModEventBus()` 获取事件总线
- 将 `modContainer.registerConfig(...)` 改为 `ModLoadingContext.get().registerConfig(...)`

#### `@EventBusSubscriber` 包路径

```java
// NeoForge 1.21.1
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.api.distmarker.Dist;

// Forge 1.20.1
import net.minecraftforge.eventbus.api.SubscribeEvent;
import net.minecraftforge.fml.common.Mod.EventBusSubscriber;
import net.minecraftforge.api.distmarker.Dist;
```

#### `@GameTestHolder` 包路径

```java
// NeoForge 1.21.1
import net.neoforged.neoforge.gametest.GameTestHolder;
import net.neoforged.neoforge.gametest.PrefixGameTestTemplate;

// Forge 1.20.1
import net.minecraftforge.gametest.GameTestHolder;
// 确认 Forge 1.20.1 是否有 @PrefixGameTestTemplate，如无则删除
```

#### `EntityAttributeCreationEvent` 包路径

```java
// NeoForge 1.21.1
import net.neoforged.neoforge.event.entity.EntityAttributeCreationEvent;

// Forge 1.20.1
import net.minecraftforge.event.entity.EntityAttributeCreationEvent;
```

### 6.3 Phase 2 迁移步骤

1. 确认 Phase 1 已全部完成（`./gradlew build` 通过、GameTest 全部 green）
2. 从 `1.21.1-neoforge` 分支复制整个 `example/` 目录到 `1.20.1-forge` 分支
3. 按 [6.2](#62-注册基础设施差异对照) 的对照表逐文件修改包 import
4. 重新构建：`./gradlew build`
5. 运行时验证：
   - `./gradlew runGameTestServer`——确认 8 个 GameTest 全部通过
   - `./gradlew runClient`——确认示例物品出现在创造模式物品栏
6. 如果 GameTest 框架在 Forge 下不可用，至少确保 `runClient` 中：
   - 示例近战武器能正常攻击靶子
   - 示例投射物能正常发射并造成伤害
   - 示例护甲四件套能正常穿戴并减免伤害

### 6.4 Phase 2 变通方案

如果 Forge 1.20.1 的 GameTest 系统与 NeoForge 差异过大，可采取以下策略：

- 将 `BallisticsGameTest.java` 标记为 Forge 分支**暂不迁移**（通过 `.gitignore` 或条件编译）
- 仅验证 `runClient` 中示例内容的功能完整性
- 在 `1.21.1-neoforge` 分支上保留完整的 GameTest 覆盖，Forge 分支回归测试依赖手动操作
