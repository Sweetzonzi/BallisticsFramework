# 3.7 代理实体：实现 BFHitResolver

## 设计动机

`BFHitResolver` 与 `BFHurtTarget` 有着明确的职责分离：

- **BFHurtTarget** 回答"打中了之后穿深多少、伤害多少"——在管线内
- **BFHitResolver** 回答"打中了谁"——在管线外

当一个实体充当其他子对象的**代理**时（例如模块化载具的部件宿主、多碰撞箱 BOSS 的碰撞代理），原版的 AABB 碰撞检测只能报告"命中了代理实体"，无法区分弹丸实际打中了哪个子部件、甚至是否真的打中了。`BFHitResolver` 让代理实体能够在伤害管线之外执行一次精确验证，将原始命中重定向到真正应该承受伤害的目标。

## 与 BFHurtTarget 的关系

一个实体**可以同时实现** `BFHitResolver` 和 `BFHurtTarget`，但它们的职责是正交的：

| 接口 | 调用时机 | 回答的问题 | 典型输入 |
|------|---------|-----------|---------|
| `BFHitResolver.resolveHit` | 在 `BFDamageApi.hurt()` 之前 | 打中了谁？真的打中了吗？ | 原版命中点 + 搜索方向 |
| `BFHurtTarget.resolvePenetration` | 在 `BFDamageApi.hurt()` 内部 | 打穿了没有？ | 完整的 BFDamageContext |

典型的代理实体会同时实现两者：`BFHitResolver` 负责将原版命中的代理实体重定向到正确的子部件；`BFHurtTarget` 在管线内为子部件的穿甲判定提供服务。

## 接口方法

`BFHitResolver` 定义了两个方法，但通常只需要实现主方法：

```java
public interface BFHitResolver {

    /** 主方法：执行精确命中验证 */
    @Nullable
    BFHitResolveResult resolveHit(Vec3 hitPoint, Vec3 delta);

    /** 便利重载：从原版 HitResult 提取命中点后委托给主方法 */
    @Nullable
    default BFHitResolveResult resolveHit(HitResult hitResult, Vec3 delta) {
        return resolveHit(hitResult.getLocation(), delta);
    }
}
```

### 参数说明

**`hitPoint`**（或 `HitResult.getLocation()`）是原版碰撞检测报告的命中点世界坐标。通常来自于 `EntityHitResult` 或自定义 raycast。这是你的精确验证的**起点**。

**`delta`** 是武器侧在调用 `resolveHitTarget` 时传入的搜索矢量。它的方向代表弹丸的飞行方向，它的模长代表从命中点继续向前搜索的距离上限（单位：米）。协议不规定这个值应该是多少——它由武器侧根据弹丸速度和帧率决定。你的实现应该以 `hitPoint` 为起点，沿 `delta` 方向搜索，但**不应超出** `delta` 的模长距离。

### 返回值

返回 `null` 表示**实际未命中**——即使原版 AABB 碰撞检测报告了命中，你的精确验证发现弹丸实际上没有碰到任何有效目标。此时调用方应让投射物继续飞行。

返回非 null 的 `BFHitResolveResult` 表示验证通过。结果中包含真正的伤害目标、修正后的命中几何和可选的扩展数据。

## 实现示例

以下展示一个代理实体实现 `BFHitResolver` 的完整模式。假设你的模组有一个模块化实体，其子部件分布在代理实体的 AABB 范围内。你需要通过射线检测来确定弹丸实际命中的子部件：

```java
public class ModularProxyEntity extends Entity implements BFHitResolver, BFHurtTarget {

    private final List<SubPart> parts = new ArrayList<>();

    @Override
    @Nullable
    public BFHitResolveResult resolveHit(Vec3 hitPoint, Vec3 delta) {
        // 从命中点沿 delta 方向执行射线检测，找到第一个有效子部件
        Vec3 searchEnd = hitPoint.add(delta);
        SubPart bestPart = null;
        double bestDist = Double.MAX_VALUE;

        for (SubPart part : this.parts) {
            if (!part.isActive()) continue;

            // 计算射线与子部件碰撞体的交点
            HitResult partHit = part.rayIntersect(hitPoint, searchEnd);
            if (partHit != null) {
                double dist = partHit.getLocation().distanceToSqr(hitPoint);
                if (dist < bestDist) {
                    bestDist = dist;
                    bestPart = part;
                    bestHit = partHit;  // 保存最近交点的结果
                }
            }
        }

        if (bestPart == null) {
            return null;  // 射线穿过所有间隙——假阳性，投射物继续飞行
        }

        // 构造扩展数据，传递子部件标识
        BFDamageExtensions exts = new BFDamageExtensions();
        exts.set(MyModKeys.PART_ID, bestPart.getId());

        return new BFHitResolveResult(
            bestPart,                        // actualTarget：真正的协议伤害目标（实现了 BFHurtTarget）
            bestHit.getLocation(),            // correctedHitPoint：子部件表面的精确命中点
            calculateHitNormal(bestHit),      // correctedHitNormal：子部件表面的精确法线
            exts                              // 扩展数据
        );
    }
}
```

关键要点：

1. **搜索范围**：以 `hitPoint` 为起点，沿 `delta` 方向搜索，不超过 `hitPoint.add(delta)`。因为 `delta` 的模长已经是武器侧根据弹丸速度估算的合理搜索距离。
2. **返回 null 的条件**：当射线穿过了所有子部件的碰撞体而没有命中任何有效目标时，返回 null。这是假阳性判断的核心——投射物应该继续飞行，不应被销毁。
3. **最近命中优先**：如果有多个子部件在搜索路径上，取距离 `hitPoint` 最近的。这也是射线检测的标准做法。
4. **扩展数据**：在 `BFHitResolveResult.extensions` 中携带与命中部位相关的元数据（如部件 ID、材质类型）。武器侧在构造上下文时会 `copy()` 这个容器并追加自己的字段。

## 两层防御体系

`BFHitResolver` 与防御侧自愈机制构成两层互补的防御体系：

```text
上层（攻击侧自动化）： 协议内置的 ProjectileHitResolverMixin
  工作原理：当任何投射物（Projectile）命中一个实现了 BFHitResolver 的实体时，
          协议自动在 onHit 执行前调用 resolveHitTarget，若返回 null 则取消
          原版 onHit 流程，投射物继续飞行。
  解决的问题：框架外武器模组的投射物在命中代理实体时，自动获得假阳性判断。
  前提：代理实体实现了 BFHitResolver。

下层（防御侧自愈）：  代理实体 BFHurtTarget.hurt() 内部的精确路由
  工作原理：当伤害已进入管线时，在 hurt() 内部通过类似 raycast 的方式
          将伤害分配到正确的子部件。
  解决的问题：即使攻击方未调用 resolveHitTarget，伤害也能正确路由。
  前提：代理实体实现了 BFHurtTarget 并在 hurt() 内有自愈逻辑。
```

**两层体系不重复**——它们解决的是不同层次的问题：

- 上层（攻击侧自动化）解决**投射物生命周期**的问题：打空了就该继续飞，不该被销毁
- 下层（防御侧自愈）解决**伤害路由正确性**的问题：打中了就该找对目标

## 完全自动化的 Mixin 支持

协议包含一个内置的 Mixin——`ProjectileHitResolverMixin`——它注入到 `Projectile.onHit(HitResult)` 的 HEAD 阶段。当任何投射物命中一个实现了 `BFHitResolver` 的实体时，此 Mixin 会自动：

1. 检查命中结果是否为 `EntityHitResult` 且目标实现了 `BFHitResolver`
2. 从投射物的 `getDeltaMovement()` 计算搜索矢量（取两 tick 飞行距离，钳制在 1~8 米）
3. 调用 `BFDamageApi.resolveHitTarget(result, delta)` 验证
4. 若返回 null，取消原版 `onHit` 流程——投射物不被销毁，继续飞行

这意味着**一旦你的代理实体实现了 `BFHitResolver`，所有投射物（无论来自哪个模组）在命中它时都会自动获得精确命中验证。** 武器模组不需要做任何额外的适配——这就是"自动化"的含义。

此 Mixin 对非 `BFHitResolver` 实体的性能影响为零——仅一次 `instanceof` 检查后直接 `return`。

## 三层防御全貌

将 `ProjectileHitResolverMixin`（上层）、`BFDamageApi.resolveHitTarget()`（中层）和防御侧自愈（下层）合在一起，构成了协议的完整三层防御体系：

```text
上层（Mixin 自动化）:  ProjectileHitResolverMixin
  拦截 Projectile.onHit → resolveHitTarget → null → cancel
  → 解决投射物生命周期问题：打空了就该继续飞

中层（协议查询）:       BFDamageApi.resolveHitTarget()
  实体版本 / HitResult 版本 → 委托 BFHitResolver
  → 为框架内攻击者提供精确命中查询

下层（防御侧自愈）:      代理实体的 hurt() 内部精确路由
  已在管线内的伤害 → 自行精确检测 → 路由到正确目标
  → 解决伤害路由问题：打中了就该找对目标
```

## 完整场景一览

以下表格展示了不同攻击路径下、不同实体类型时的行为：

| 攻击方 | 代理实体实现 | 触发链 | 结果 |
|--------|------------|--------|------|
| 框架内武器模组（手动调用 resolveHitTarget） | 实现 BFHitResolver | 攻击方手动 resolveHitTarget → 获精确几何 → hurt(SubPart) | 精确命中 + 假阳性判断 |
| 任意投射物 | 实现 BFHitResolver | ProjectileHitResolverMixin 自动拦截 onHit → resolveHitTarget → null → cancel | 全自动，投射物不被销毁 |
| 任意投射物 | 实现 BFHitResolver | ProjectileHitResolverMixin → resolveHitTarget → 找到目标 → 放行 onHit | 全自动，精确命中 |
| 框架外武器模组（直接 entity.hurt） | 实现 BFHitResolver + BFHurtTarget（有自愈） | entity.hurt → Mixin 拦截 → 协议管线 → hurt 内自愈路由 | 伤害正确路由（假阳性已在上层解决） |
| 框架外武器模组（直接 entity.hurt） | 仅实现 BFHurtTarget（无自愈） | entity.hurt → 原版流程 | 伤害作用在代理实体自身 |

从表格可以看出，**最坚固的防护是同时实现 `BFHitResolver` 和 `BFHurtTarget`（含自愈）**——这样可以覆盖所有攻击路径。仅实现 `BFHitResolver` 能自动获得上中两层的保护，所有投射物攻击都会经过精确验证。

## BFHitResolver 不是必须的

如果你的实体不是代理实体——即它的 AABB 就是它的真实碰撞体，没有子部件，不需要假阳性判断——你**不需要**实现 `BFHitResolver`。只需要实现 `BFHurtTarget` 就足够了。`BFHitResolver` 的价值仅在于"代理实体需要将命中重定向到子目标"的场景。

## 与 BFArmorMaterial 的配合

如果你的代理实体本身也穿戴了协议护甲，`BFHitResolver` 在 `resolveHitTarget` 中先于 `BFArmorAdapter` 生效。这意味着命中前解析返回的 `correctedHitPoint` 和 `correctedHitNormal` 可以用于护甲侧的部位映射——护甲物品的 `mapHitToSlot` 可以使用修正后的精确命中点来判断着弹槽位。

典型的串联流程如下：

1. 投射物命中代理实体的 AABB → `ProjectileHitResolverMixin` 触发
2. `resolveHitTarget(EntityHitResult, delta)` → 代理实体的 `BFHitResolver.resolveHit()` 返回子部件
3. 武器侧用 `correctedHitPoint` 和 `correctedHitNormal` 构造 `BFDamageContext`
4. `BFDamageApi.hurt(subPart, ctx)` → 如果子部件穿戴了协议护甲，进行双层串联判定
