# 1.5 武器模组：弹道解算

外弹道解算器是武器模组开发者的核心工具——在有重力和阻力的弹道下，枪口不能直接指向目标。本节展示从零开始的三种最简用法：正解（算弹丸轨迹）、反解（算瞄准方向）、提前量（算移动目标的预瞄点）。

## 第一步：选择模型

在写任何代码之前，先判断你的弹丸用哪种物理模型：

```
弹丸是什么类型？
├── 基于原版 Projectile / ThrowableProjectile（箭、雪球、火球等）
│     → 用 MinecraftTrajectory
├── 自定义物理，阻力 = 速度 × 常数（MC 风格速度乘数）
│     → 用 MinecraftTrajectory（通用版，传入 dragH/dragV）
└── 自定义物理，阻力 = ½·ρ·Cd·A·v²/m（二次空气阻力）
      → 用 RealisticTrajectory
```

## 最简示例：正解——弹丸飞哪去

拿到弹丸实体的当前速度，预测其完整飞行轨迹：

```java
// MC 原版箭矢正解
Vec3 arrowVel = arrowEntity.getDeltaMovement();  // 单位 m/tick，与原版一致
TrajectoryResult traj = MinecraftTrajectory.arrowTrajectory(
    arrowEntity.position(), arrowVel, 100
);

// 从正解结果直接填入命中上下文
BFDamageContext hitCtx = BFDamageContext.builder()
    .source(damageSource)
    .baseDamage(35f)
    .hitPoint(traj.terminalPoint())          // 弹丸最终位置
    .hitVelocity(traj.terminalVelocity())    // 末速 m/s，直传
    .hitNormal(traj.approximateHitNormal())  // 法线近似
    .penetration(calcPen(traj))              // 根据末速衰减后的穿深
    .build();
```

拟真模型的正解需要先构造弹丸参数。如果用到了 `BFDamageExtensions` 中预定义的 `CALIBER` 和 `MASS`，只需额外传入阻力系数 Cd：

```java
// 拟真模型正解——120mm 坦克炮 APFSDS
BallisticConfig config = BallisticConfig.fromExtensions(
    exts, 0.35f,    // Cd——唯一要手动给的参数，其余从 CALIBER/MASS 读
    0.8f,           // MC 主世界重力 (m/s²)
    0.05f,          // 步长 1 tick
    200
);
TrajectoryResult traj = RealisticTrajectory.forwardSolve(
    shooterPos, new Vec3(0, 0, 1500),   // 初速 1500 m/s 向正 Z 轴
    config, DensityFunction.MC_OVERWORLD
);
```

> **注意**：MC 模型入参是 m/tick，拟真模型入参是 m/s。输出统一为 m/s——与 `BFDamageContext.hitVelocity` 一致，直接传递即可。

## 最简示例：反解——AI 炮塔自动瞄准

已知目标和初速标量，反解出射方向。适用于炮塔 AI、僵尸瞄准辅助、弹道指示器等：

```java
// MC 原版箭矢反解——一行调用
List<FiringSolution> solutions = MinecraftTrajectory.arrowFiringAngle(
    turretPos, targetPos,
    6.0f,              // 初速 (m/tick)
    turretVelocity,    // 炮塔自身速度（移动平台），固定炮塔传 Vec3.ZERO
    200
);

if (solutions.isEmpty()) {
    // 初速不足，无法命中——靠近目标或换高速弹药
    return;
}

FiringSolution lowArc = solutions.get(0);   // 平射解
// lowArc.direction() → 直接设为弹丸的 deltaMovement 方向
arrowEntity.setDeltaMovement(
    lowArc.direction().scale(6.0f).add(turretVelocity)
);
```

拟真模型的反解同样需要 `BallisticConfig`：

```java
List<FiringSolution> solutions = RealisticTrajectory.solveFiringAngle(
    turretPos, targetPos, 1500f,      // 初速 1500 m/s
    turretVelocity,                    // 发射者速度 (m/s)
    config, DensityFunction.MC_OVERWORLD,
    0.01f                              // angleEpsilon
);
```

初速充足时返回两个解——`solutions.get(0)` 是平射解（飞行时间短），`solutions.get(1)` 是高抛解（可翻越障碍物）。临界初速时仅返回一个解，初速不足时返回空列表。

## 最简示例：提前量——射击移动目标

目标在移动时，不能瞄当前位置——需要预测弹丸飞行时间后目标的位置：

```java
// MC 原版——箭矢对移动玩家预测提前量
FiringSolution lead = MinecraftTrajectory.arrowWithLead(
    shooterPos,
    playerEntity.position(),              // 目标当前位置
    playerEntity.getDeltaMovement(),      // 目标速度 (m/tick)
    Vec3.ZERO,                            // 目标加速度（玩家通常匀速）
    6.0f,                                 // 初速
    shooter.getDeltaMovement(),            // 发射者自身速度
    200
);
```

```java
// 拟真模型——防空炮塔对飞行目标预测提前量
FiringSolution lead = RealisticTrajectory.solveWithLead(
    shooterPos,
    target.position(),
    target.getDeltaMovement().scale(20),   // m/tick → m/s
    Vec3.ZERO,
    2000f,                                 // 初速 2000 m/s
    Vec3.ZERO,
    config, DensityFunction.MC_OVERWORLD,
    6, 0.1f                                // maxIterations, convergeEpsilon
);
```

解算器先用 `distance/speed` 做首次粗略外推，再迭代微调——典型场景 2~4 轮收敛。即使未收敛也返回当前最优猜测，永不返回 null。

## 两类解算器共有的特性

无论选择 MC 原版还是拟真模型，以下特性都适用：

- **退化路径自动识别**：重力为零时走匀速直线（激光武器），无阻力时走解析抛物线公式——无需用户配置
- **共享输出数据结构**：`TrajectoryResult`、`FiringSolution` 在两个模型间通用，下游代码零切换
- **`static` 方法，线程安全**：服务器 AI、客户端预览、物理线程异步计算均可调用
- **与终点弹道无缝衔接**：`terminalVelocity()` 直传 `BFDamageContext.hitVelocity`，单位一致
