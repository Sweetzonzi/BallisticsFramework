# 1.4 护甲模组：响应协议伤害

护甲侧开发者的职责是让自己的实体实现 `TBHurtTarget` 接口，声明"我会自行处理穿甲判定和伤害后果"。协议提供了一套完整的默认实现——简单模式只需一个方法即可获得穿甲判定能力；精密模式下可逐层覆写，深度自定义判定逻辑。

## 最简示例：简易模式

对于一个只需要"某种装甲能防住某种枪"的简单模组，只需让实体实现 `TBHurtTarget`，并覆写两个方法——`getArmorLevel` 和 `hurt`：

```java
public class ArmoredZombie extends Zombie implements TBHurtTarget {

    @Override
    public ArmorLevel getArmorLevel(TBDamageContext ctx) {
        // 根据命中部位返回不同等级，此处简化为固定值
        return ArmorLevel.HEAVY;  // 40~80mm，相当于步战车正面装甲
    }

    @Override
    public boolean hurt(DamageSource source, float amount) {
        // 经协议计算后的最终伤害量，委托给原版管线
        return super.hurt(source, amount);
    }

    @Override
    @Nullable
    public TBDamageContext createContextFromVanilla(DamageSource source, float amount) {
        // 返回 null 表示原版伤害不走协议管线
        // 如果要让原版攻击也走穿甲判定，应构造一个低信息量上下文
        return null;
    }
}
```

这就是护甲侧最简实现。当武器侧通过 `TBDamageApi.hurt()` 发起协议伤害时，协议会调用 `getArmorLevel` 获取离散护甲等级，然后自动完成穿甲判定和伤害计算——基于等级比较（等于算击穿）、默认的三级伤害模型（刚好击穿 65%、越级击穿 100%、未击穿 0）。

## 理解协议外伤害兼容

上面的代码中还有一个 `createContextFromVanilla` 方法返回了 `null`，这意味着**原版生物攻击、TNT 爆炸等非协议来源的伤害命中此实体时，将完全走原版流程**——就像这个实体没有实现 `TBHurtTarget` 一样。这是大多数情况下推荐的做法。

如果你希望原版伤害也被装甲减免，可以在 `createContextFromVanilla` 中构造一个低信息量的上下文：

```java
@Override
@Nullable
public TBDamageContext createContextFromVanilla(DamageSource source, float amount) {
    // 将原版伤害量作为 baseDamage，弹道字段用零值
    return TBDamageContext.builder()
        .source(source)
        .baseDamage(amount)
        .build();
}
```

这样即便是被僵尸捶了一拳，也会走穿甲判定——如果装甲等级高于伤害默认的零穿深，僵尸的攻击将被判定为未击穿（最终伤害为 0）。

## 根据命中部位返回不同等级

真实的装甲实体通常不同部位的防护能力不同。`getArmorLevel` 接收完整的 `TBDamageContext`，你可以据此判断命中点落在哪个部位：

```java
@Override
public ArmorLevel getArmorLevel(TBDamageContext ctx) {
    // 获取命中点在实体局部坐标中的位置
    Vec3 localHit = ctx.hitPoint().subtract(this.position());

    // 前方 120° 范围为正面（最强防护）
    double yRot = Math.toRadians(this.getYRot());
    double dx = localHit.x * Math.cos(yRot) + localHit.z * Math.sin(yRot);

    if (dx > 0.5) {
        return ArmorLevel.SUPER_HEAVY_3;   // 正面：300~600mm（冷战MBT级）
    } else if (dx > -0.5) {
        return ArmorLevel.HEAVY;           // 侧面：40~80mm
    } else {
        return ArmorLevel.MEDIUM;          // 后方：20~40mm
    }
}
```

这是简易模式的优势所在——你几乎不需要理解 RHA 数值的细节，只需决定每个部位落在哪个等级区间，协议就会自动处理余下的一切。

## 在 hurt 方法内获取上下文

协议伤害进入 `hurt` 时，此时上下文仍然有效。如果你的实体需要在执行伤害时读取命中相关信息——例如播放命中点附近的音效、在命中面法线方向生成粒子——可以在 `hurt` 内通过 `TBDamageApi.getContextFor(this)` 获取当前上下文：

```java
@Override
public boolean hurt(DamageSource source, float amount) {
    TBDamageContext ctx = TBDamageApi.getContextFor(this);
    if (ctx != null) {
        // 在命中点播放火花音效
        this.level().playSound(null, ctx.hitPoint().x, ctx.hitPoint().y, ctx.hitPoint().z,
            SoundEvents.ANVIL_LAND, SoundSource.PLAYERS, 0.5f, 1.0f);
    }
    return super.hurt(source, amount);
}
```

## 何时需要精密模式

简易模式适用于"这个怪有三级甲"这样的场景。当你的装甲系统需要毫米级精度——比如基于复合装甲的等效厚度公式、爆反的拦截概率、间隙装甲的衰减系数——就需要进入精密模式。

精密模式不需要彻底抛弃简易模式。`TBHurtTarget` 的每个管线方法都是 `default` 方法，你可以只覆写需要定制的步骤，其余步骤继续使用默认实现。例如，一个实体可以保留简易模式的 `getArmorLevel` 用于显示和通用查询，同时覆写 `getRHA` 和 `modifyPenetration` 来做精确计算：

```java
@Override
public float getRHA(TBDamageContext ctx) {
    // 基于角度和材料参数计算的精确等效厚度
    float baseThickness = 150f;              // 基础物理厚度
    float angleFactor = ...;                 // 根据命中角度计算
    float materialFactor = 1.2f;             // 材料系数
    return baseThickness * angleFactor * materialFactor;
}

@Override
public float modifyPenetration(TBDamageContext ctx) {
    // 爆反拦截：50% 概率减少 100mm 穿深
    float base = ctx.penetration();
    if (this.level().random.nextFloat() < 0.5f) {
        return Math.max(0, base - 100f);
    }
    return base;
}

@Override
public PenetrationResult resolvePenetration(TBDamageContext ctx) {
    float rha = getRHA(ctx);
    float effectivePen = modifyPenetration(ctx);
    // 入射角 > 70° 则跳弹
    // ... 自定义跳弹判定逻辑
    if (effectivePen > rha) {
        return PenetrationResult.PENETRATED;
    }
    return PenetrationResult.BLOCKED;
}
```

每次覆写的具体细节——`getRHA` 的精确计算、`modifyPenetration` 的拦截模型、跳弹的判定算法——将在第三章中逐一展开。
