# 5.2 弹道正解

> **问题**："从 A 点以速度 v 射出，弹丸的飞行轨迹是什么？最终落在哪？末速是多少？"

弹道正解（forward solve）是外弹道模块最基础的能力——给定发射位置、初速度矢量和物理参数，解算器逐步模拟弹丸的运动状态，返回按时间升序排列的轨迹采样点。反解和提前量都依赖正解作为底层计算——每猜一个仰角就做一次正解看结果。因此正解的性能和准确性直接影响整个外弹道系统。

---

## 数据结构

### TrajectorySample —— 单个采样点

```java
TrajectorySample(float time, Vec3 position, Vec3 velocity)
```

| 字段 | 说明 |
|------|------|
| `time` | 自发射起经过的时间（s），首点 time=0 |
| `position` | 弹丸世界坐标（m），1 格 = 1 m |
| `velocity` | 瞬时速度矢量（**m/s**，统一输出单位） |

相邻两点的 `time` 差即积分步长。MC 模型下步长固定为 0.05s（1 tick），拟真模型下步长由用户配置。

为什么要同时存速度和位置？弹道可视化需要轨迹点坐标，但计算命中穿深时需要末速——两者放同一条记录中，取末速不必再推算。

### TrajectoryResult —— 正解结果

```java
TrajectoryResult(List<TrajectorySample> samples)
```

构造时自动防御性拷贝（`List.copyOf`），返回的实例不可变。提供以下便捷方法：

| 方法 | 返回值 | 用途 |
|------|--------|------|
| `first()` | TrajectorySample | 发射点——确认起点是否正确 |
| `last()` | TrajectorySample | 终点——达 maxSteps/maxTicks 时的采样点 |
| `totalTime()` | float | 总飞行时间（s） |
| `terminalPoint()` | Vec3 | 终点坐标 → `BFDamageContext.hitPoint` |
| `terminalVelocity()` | Vec3 | 末速度（m/s） → `BFDamageContext.hitVelocity`，可直接传入 |
| `approximateHitNormal()` | Vec3 | 末速度反方向归一化 → `BFDamageContext.hitNormal`（近似值） |

正解**不判断"是否命中目标"**——它是纯物理模拟，输出的是弹丸在空间中的运动轨迹。是否命中由你根据 `terminalPoint()` 与目标的距离自行判断。解算器仅以 maxSteps/maxTicks 为终止条件——MC 世界 Y 坐标可深至 -64（深暗之域），不存在固定的"地平面"，调用方应根据实际地形自行判断弹丸是否触地。

## MC 原版模型的正解

### 原理

MC 弹射物（箭、雪球、火球等）每 tick 物理更新使用**类型 A** 计算顺序：

```
v.y += gravity      // 加速度
v.x *= dragH       // 水平阻力（速度乘数）
v.y *= dragV       // 垂直阻力
v.z *= dragH
p += v             // 位置更新
```

阻力是速度乘数（如 0.99 表示每 tick 保留 99% 速度），与质量、速度大小无关。

### 使用方式

**如果你在使用原版弹射物**，直接调用便捷方法并传入实体速度即可：

```java
// 箭矢——直接从实体取 deltaMovement，单位 m/tick
Vec3 shotVel = arrowEntity.getDeltaMovement();
TrajectoryResult traj = MinecraftTrajectory.arrowTrajectory(
    arrowEntity.position(), shotVel, 100
);
```

可用的便捷方法：`arrowTrajectory`、`snowballTrajectory`、`fireballTrajectory`、`potionTrajectory`、`bottleTrajectory`。

**如果你自定义了弹射物但使用同样的速度乘数阻力模型**，调用通用版传入自定义参数：

```java
TrajectoryResult traj = MinecraftTrajectory.forwardSolve(
    start, velocity,         // Vec3 (m/tick)
    0.98f, 0.97f,            // dragH, dragV —— 你的自定义阻力系数
    -0.04f,                  // gravity —— 你的自定义重力
    150                      // maxTicks
);
```

内置的 6 组实体预设常量通过静态内部类组织，IDE 输入 `MinecraftTrajectory.` 即可自动补全：

| 内部类 | gravity | dragH | dragV | 代表实体 |
|--------|:---:|:---:|:---:|------|
| `Arrows` | -0.05 | 0.99 | 0.99 | 箭、三叉戟 |
| `Snowballs` | -0.03 | 0.99 | 0.99 | 雪球、鸡蛋、末影珍珠 |
| `Potions` | -0.05 | 0.99 | 0.99 | 喷溅药水 |
| `BottlesOfEnchanting` | -0.07 | 0.99 | 0.99 | 附魔之瓶 |
| `Fireballs` | +0.10 | 0.95 | 0.95 | 火球、凋灵之首（**向上漂**） |
| `LlamaSpit` | -0.06 | 0.99 | 0.99 | 羊驼唾沫 |

注意 `Fireballs` 的 gravity 是**正值**——火球天然向上漂，`v.y += 0.10` 每 tick。

## 拟真模型的正解

### 原理

基于牛顿力学 + 标准空气阻力方程，使用半隐式欧拉法积分：

```
每步 Δt:
  v_mag = |v|
  a_drag = -0.5 · ρ(pos) · Cd · A · v_mag · v / m
  v_new = v + (g + a_drag) · Δt          // 半隐式欧拉
  p_new = p + v_new · Δt
```

阻力与速度平方成正比（高速下阻力急剧增大）、与质量成反比（重弹减速慢）、与截面积成正比（细弹阻力小）。每步调用 `DensityFunction` 获取当前位置的空气密度——高空空气稀薄，阻力减小。

### BallisticConfig —— 弹丸参数

使用拟真模型前需要构造 `BallisticConfig`。它包含 6 个参数：

| 参数 | 说明 | 从哪里来 |
|------|------|------|
| `dragCoefficient` (Cd) | 阻力系数，无量纲，典型 0.2~0.5 | 你手动指定 |
| `mass` | 弹丸质量（kg） | `exts.get(MASS)` |
| `crossSectionArea` | 横截面积（m²），π·(d/2)² | 从 `exts.get(CALIBER)` 计算 |
| `gravity` | 重力加速度（m/s²），MC 主世界 ≈ 0.8 | 你手动指定 |
| `timeStep` | 时间步长（s），默认 0.05 = 1 tick | 通常默认即可 |
| `maxSteps` | 最大步数，默认 200 | 长距离射击可增大 |

**两种构造方式**：

```java
// 方式 1：从 BFDamageExtensions 自动读取口径和质量（推荐）
BFDamageExtensions exts = new BFDamageExtensions();
exts.set(BFDamageExtensions.CALIBER, 0.12f);   // 120mm 口径 (m)
exts.set(BFDamageExtensions.MASS, 8.5f);       // 8.5kg 弹丸

BallisticConfig config = BallisticConfig.fromExtensions(
    exts,
    0.35f,     // Cd —— 唯一要手动给的参数
    0.8f,      // 重力 (m/s²)
    0.05f,     // Δt
    200        // maxSteps
);

// 方式 2：便捷构造（口径、质量直接传，不打扩展容器）
BallisticConfig config = BallisticConfig.simple(
    0.35f, 0.12f, 8.5f,   // Cd, 口径 m, 质量 kg
    0.8f                   // 重力
);
// 该重载自动使用 timeStep=0.05, maxSteps=200
```

`fromExtensions` 的优势在于与 `BFDamageExtensions` 的数据流闭环——口径和质量已经在 `CALIBER` 和 `MASS` 中定义过了，你只需额外传入 Cd。

### DensityFunction —— 空气密度

每积分步解算器调用一次 `density.getDensity(pos)` 获取该位置的空气密度。内置三个预设：

| 预设 | 行为 | 适用场景 |
|------|------|------|
| `DensityFunction.MC_OVERWORLD` | Y=62 处 1.225 kg/m³，标高 8500m 指数衰减 | 主世界通用 |
| `DensityFunction.SEA_LEVEL` | 全高度恒定 1.225 | 低弹道平射（几十米内无需考虑密度衰减） |
| `DensityFunction.VACUUM` | 恒返回 0 ——无阻力 | 激光武器、下界、太空 |

自定义密度函数——根据维度或地形调整：

```java
// 根据维度选择
Level level = ...;
DensityFunction density = switch (level.dimension().location().toString()) {
    case "minecraft:the_nether"  -> DensityFunction.VACUUM;
    case "minecraft:the_end"     -> DensityFunction.constant(0.3f);
    default -> DensityFunction.standardBarometric(level.getSeaLevel(), 8500);
};

// 或更复杂的自定义逻辑
DensityFunction custom = pos -> {
    float baseDensity = 1.225f * (float)Math.exp(-(pos.y - 62) / 8500);
    if (pos.y > 255) return 0f;       // 建筑物高度以上无大气
    if (pos.y < -60) return 2.0f;      // 地下高压
    return baseDensity;
};
```

### 使用方式

```java
TrajectoryResult traj = RealisticTrajectory.forwardSolve(
    startPos,                              // Vec3 (m)
    new Vec3(0, 0, 1500),                  // 初速 1500 m/s 向正 Z 轴
    config,                                // BallisticConfig
    DensityFunction.MC_OVERWORLD
);
```

> 拟真模型的 speed 单位是 **m/s**。1500 m/s 约等于 5400 km/h，已经是超音速（海平面音速 ~343 m/s）。如果只想让弹丸飞几十米，把初速设为 50~100 m/s 即可。

## 退化路径：自动 O(1) 优化

解算器在方法入口检查参数，当模型退化为简单运动时跳过迭代、走解析路径。你不需要做任何配置——传入参数后自动选择最优路径：

| 条件 | 正解路径 | 典型场景 |
|------|------|------|
| g=0, 无阻力 | 匀速直线运动 | 激光武器、下界飞行弹丸 |
| g≠0, 无阻力 | 纯抛物线（仍分步积分，保证采样点粒度） | 下界射箭 |
| g=0, 有阻力 | 直线减速（速度方向不变，仅模长衰减） | 零重力空间战斗 |
| 其他 | 完整数值积分 | 通用情况 |

## 正解结果怎么用：衔接终点弹道

正解的输出可以直接填入 `BFDamageContext` 的命中几何字段，完成"外弹道 → 终点弹道"的数据传递：

```java
TrajectoryResult traj = /* 某种解算 */;

BFDamageContext hitCtx = BFDamageContext.builder()
    .source(damageSource)
    .baseDamage(500f)
    .hitPoint(traj.terminalPoint())          // 命中点 → 部位判定
    .hitVelocity(traj.terminalVelocity())    // 末速 → 残余穿深计算，同为 m/s
    .hitNormal(traj.approximateHitNormal())  // 法线近似 → 入射角计算
    .penetration(calcResidualPen(traj))      // 根据末速衰减后的穿深
    .extensions(baseExts.copy())
    .build();

BFDamageApi.hurt(target, hitCtx);
```

> **注意**：`approximateHitNormal()` 返回的是末速度反方向，仅为法线近似——它假设弹丸最终沿其速度方向命中平面。对于精确的斜面装甲命中法线，应通过射线检测或碰撞盒解析获取真实几何法线。

## 弹道可视化与轨迹渲染

正解的采样点列表天然适合弹道可视化。以下是一个简单的渲染器思路（每帧取采样点画线）：

```java
// 弹道预览 HUD：缓存正解结果，每帧绘制一次
TrajectoryResult cachedTraj = ...; // 每几帧更新一次

for (int i = 1; i < cachedTraj.samples().size(); i++) {
    TrajectorySample prev = cachedTraj.samples().get(i - 1);
    TrajectorySample curr = cachedTraj.samples().get(i);
    drawLine(prev.position(), curr.position(), color);
}
```

60 FPS 弹道预览的建议——正解一次耗时 ~5~15 μs，完全可以每帧调用。但如果一个 tick 需要处理数百个目标的 AI 瞄准（走反解而不是正解），建议分帧或缓存。
