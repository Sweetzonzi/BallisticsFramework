# 5.4 动目标提前量

> **问题**："目标是移动的，弹丸飞过去要时间——到那时目标已经不在原位了。该瞄它前方哪里？"

静态反解假设目标是固定不动的。当目标在移动（步行的玩家、飞行的凋灵、行驶的载具），弹丸飞行期间目标会位移——瞄当前位置几乎必然打空。动目标提前量（lead prediction）在反解之上叠加一层迭代，逐步预测目标在弹丸飞行时间后的位置，并以此为瞄准点。

---

## 算法原理

算法分三步迭代循环：

```
                    ┌────────────────────────────────┐
                    │ 0. 粗略外推（不在迭代计数内）       │
                    │    roughTime ≈ distance / speed   │
                    │    predictedPos = P + V·roughTime  │
                    └──────────────┬─────────────────┘
                                   ▼
┌──────────────────────────────┐
│ 1. 以 predictedPos 为目标做反解  │  ← 从外推位置开始，而非当前位置
│    → 得到 flightTime           │
├──────────────────────────────┤
│ 2. 预测新位置：                  │
│    P_new = P_current + V·t + ½·a·t²  │
├──────────────────────────────┤
│ 3. predictedPos = P_new      │
│    如果 |Δ| < ε → 收敛，退出    │
│    否则 → 回到步骤 1            │
└──────────────────────────────┘
```

每次迭代，弹丸飞行时间都会略有变化（因为预测点变动），新的飞行时间产生新的预测位置——逐步逼近真正的命中点。由于首次粗略外推已使起点靠近收敛点，典型场景下 2~4 次迭代即可收敛。

**为什么需要迭代**：乍一看似乎一步就能求出——用当前位置反解获得 t，预测新位置，结束。但新位置会导致飞行时间的微小变化——这又影响预测的新位置——构成了一个递归关系。迭代就是让这个关系收束的过程。

---

## FiringSolution 的额外信息

提前量返回的 `FiringSolution` 与反解的相同，但 `iterations` 字段具有特殊含义——它记录实际迭代次数。如果 `iterations == maxIterations`，说明未收敛就已停止（属于"当前条件下最优猜测"）。

---

## MC 原版模型的提前量

### 使用方式

```java
// 箭矢——对移动玩家预测提前量
FiringSolution lead = MinecraftTrajectory.arrowWithLead(
    shooterPos,                       // 发射位置
    playerEntity.position(),          // 目标当前位置
    playerEntity.getDeltaMovement(),   // 目标速度 (m/tick)
    Vec3.ZERO,                        // 目标加速度——玩家通常是匀速
    6.0f,                             // 初速 (m/tick)
    shooter.getDeltaMovement(),        // 发射者自身速度
    200                                // maxTicks
);

// 如果 lead 不为 null，调用 lead.direction() 获得瞄准方向
```

可用的便捷方法：`arrowWithLead`、`snowballWithLead`、`fireballWithLead`。

### 通用版

```java
FiringSolution lead = MinecraftTrajectory.solveWithLead(
    start,
    targetPos, targetVel, targetAccel,
    speed, shooterVel,
    dragH, dragV, gravity,
    maxTicks,
    8,         // maxIterations —— 最大迭代次数（推荐 4~7）
    0.1f       // convergeEpsilon —— 收敛阈值 (m)
);
```

## 拟真模型的提前量

拟真模型的提前量参数通过 `BallisticConfig` 和 `DensityFunction` 封装：

```java
FiringSolution lead = RealisticTrajectory.solveWithLead(
    start,
    targetPos, targetVel, targetAccel,
    speed,                    // m/s
    shooterVel,               // m/s
    config,
    DensityFunction.MC_OVERWORLD,
    8,                        // maxIterations（推荐 4~7）
    0.1f                      // convergeEpsilon
);
```

### 参数建议

| 参数 | 推荐值 | 说明 |
|------|:---:|------|
| `maxIterations` | 4~7 | 太小可能不收敛，太大浪费性能。首次粗略外推已使起点靠近收敛点，大多数场景 3~4 次足够 |
| `convergeEpsilon` | 0.1 m | 预测位置变化小于 10cm 时认为收敛。MC 碰撞检测 AABB 膨胀本身就有 0.1m 以上误差，更小的阈值没有实际意义 |

---

## 迭代发散保护

极端情况下迭代可能发散——特别是目标速度接近弹丸速度时：

| 场景 | 风险 |
|------|------|
| 低速弹丸（50 m/s）射击高速目标（30 m/s） | 预测位置每次大幅偏移，迭代振荡 |
| 目标加速度剧烈变化 | 匀加速假设不再成立 |
| 弹丸初速恰好临界 | 反解本身就不稳定 |

解算器提供**三重保护**：

1. **`maxIterations` 硬限制**——达到上限后强制停止，不会无限循环
2. **`convergeEpsilon` 阈值**——预测位置变化小于此值时提前退出
3. **最优猜测返回**——即使未收敛也返回最后一轮的解，**永不返回 null 或空值**。调用方不需要处理"未收敛"异常

在典型武器模组场景（弹丸速度 >> 目标速度）中，发散几乎从不发生。只有在刻意制造极端对比（弹丸 30 m/s、目标 28 m/s）时才需要关注。

---

## targetAcceleration：什么时候需要

大多数场景下目标加速度 `Vec3.ZERO` 就够用了——玩家和生物的加速度通常很小。但在以下场景中传入非零加速度能显著提高准确度：

| 场景 | targetAcceleration 从哪取 |
|------|------------------------|
| 飞行的恶魂/幻翼（垂直振荡） | 比较 `targetVel` 当前帧与上一帧的差 / tick 距 |
| 加速中的载具 | 从载具的引擎推力推算 |
| 抛物线坠落中的实体 | `(0, -0.04, 0)` —— MC 重力 m/tick² |

加速度的预测公式是 `½·a·t_flight²`——即使加速度很小，飞行时间较长时此项也不可忽略。例如 0.04 m/tick² 的重力加速度在 2 秒飞行（40 tick）中会产生 `½ × 0.04 × 40² = 32` 格的偏移——这量级已经远大于命中判断的容错。

---

## 发射者速度的双重作用

提前量场景中发射者速度有两个作用：

1. **改变弹丸初速度**：`worldVel = dir × speed + shooterVel`（与反解相同）
2. **改变相对速度**：如果发射者自身也在移动，那么发射者与目标的相对速度才是迭代中真正影响预测精度的量

如果你在追逐中的载具上射击逃跑的目标，目标速度 `30 m/s`、你自身速度 `25 m/s`——弹丸的绝对初速减少了 25 m/s，而目标的相对速度是 5 m/s。这些都在解算器内部自动处理——你只需要分别正确传入 `shooterVelocity` 和 `targetVelocity`。

## 完整示例：防空炮塔

防空炮塔需要对空中快速移动的目标（如飞行玩家、恶魂）做提前量预测。以下代码展示完整的数据流：

```java
public class AACannonAI {
    private static final float MUZZLE_VELOCITY = 2000f;   // m/s
    private static final int MAX_ITER = 6;

    private Vec3 aimDir = null;

    public void tick() {
        if (this.tickCount % 5 != 0) return;  // 每 5 tick (0.25s) 更新一次

        Entity target = this.currentTarget;
        if (target == null) return;

        // 估算目标加速度：对比上一帧速度
        Vec3 targetAccel = target.getDeltaMovement()
            .subtract(this.lastTargetVel).scale(20);  // m/tick → m/s 再除以 Δt
        this.lastTargetVel = target.getDeltaMovement();

        BallisticConfig config = BallisticConfig.simple(
            0.3f,      // Cd——高射炮穿甲弹
            0.04f,     // 口径 40mm
            0.9f,      // 质量 0.9kg
            0.8f       // 重力
        );

        FiringSolution lead = RealisticTrajectory.solveWithLead(
            this.position(),
            target.position(),
            target.getDeltaMovement().scale(20),   // m/tick → m/s
            targetAccel,
            MUZZLE_VELOCITY,
            this.getDeltaMovement().scale(20),
            config,
            DensityFunction.MC_OVERWORLD,
            MAX_ITER, 0.1f
        );

        if (lead != null && lead.iterations() <= MAX_ITER) {
            this.aimDir = lead.direction();
            this.predictedHitTime = lead.flightTime();
        }
    }

    public void fire() {
        if (this.aimDir == null) return;
        Vec3 worldVel = this.aimDir.scale(MUZZLE_VELOCITY)
            .add(this.getDeltaMovement().scale(20));
        spawnShell(this.position(), worldVel);
    }
}
```

## 什么时候用提前量 vs 什么时候用反解就够了？

| 条件 | 用什么 | 原因 |
|------|--------|------|
| 目标不动（静止玩家、挂机实体） | 反解 | 预测位置 = 当前位置，迭代一步就收敛 |
| 目标慢速移动（< 2 m/s） + 弹丸高速（> 100 m/s） | 反解通常够 | 飞行时间短（< 0.2s），目标几乎不动 |
| 目标中速移动（2~10 m/s） + 弹丸中速（> 50 m/s） | 提前量 | 飞行 1 秒目标已移动 5 米——偏差超出命中范围 |
| 目标高速移动 + 弹丸低速 | 提前量 + 降低期望 | 迭代可能振荡，需要保护机制；实操中提高射速比提高精度更有效 |
| AI 必须命中（剧情事件） | 反解（不需要提前量） | 你可以在反解时直接取 "移动到准星瞬间" 的目标位置来"作弊" |

实操经验：大多数模组的弹丸速度（100~3000 m/s）远超玩家/生物的移动速度（~5~10 m/s），提前量预测通常只需要 2~3 次迭代即收敛。只有在故意设计低速弹丸（如 RPG-7 的 115 m/s 初速）时才需要关注迭代发散。
