# 5.1 外弹道概述

## 动机：为什么需要外弹道？

BallisticsFramework 的核心是**终点弹道**——从"命中瞬间"开始的穿甲判定与伤害协商。这回答了"命中后怎么办"，但没有回答"**如何命中**"。

武器模组的开发者面临一个高频问题：已知目标位置和初速，子弹该往哪个方向打？这不仅仅是"枪口指向目标"——在有重力、有空气阻力的弹道下，枪口必须向上抬高。抬高多少取决于距离、初速和弹道参数。这是一个典型的**两点边值问题**（已知起止位置，求初速方向），没有显式解析解，需要数值方法求解。

写出一个正确的弹道解算器不是简单的事。时间步长选择、数值方法收敛性、高抛/平射双根搜索、动目标迭代振荡发散——每个都是陷阱。外弹道模块把这些复杂度封装起来，让武器模组从"自行实现 ~200 行数值方法"简化为"调一个方法"。

## 三种解算能力

外弹道模块提供三种独立但互相关联的解算能力：

| 能力 | 问题 | 输入 | 输出 |
|------|------|------|------|
| **正解**（forward solve） | "从 A 点以速度 v 射出，弹丸的飞行轨迹是什么？" | 发射点、初速度、物理参数 | 轨迹采样点列表 `TrajectoryResult` |
| **反解**（firing angle） | "从 A 点以初速 s 射击 B 点，枪口该指向什么方向？" | 发射点、目标点、初速标量 | 出射方向 `FiringSolution`（0~2 个解） |
| **提前量**（lead prediction） | "目标在移动，该瞄它前方哪里？" | 发射点、目标位置+速度+加速度 | 瞄准解 `FiringSolution`（迭代收敛） |

三种能力的关系：反解本质上是一系列正解的枚举搜索——每猜一个仰角就做一次正解、看落点离目标有多远、调整仰角再试。提前量则是在这个外层再加一层迭代——每猜一个预测位置就做一次反解、更新预测位置、再重演。正解的性能决定了整个外弹道系统的性能上限。

## 两类物理模型：什么时候该用哪个？

弹道解算的核心差异是**阻力形式**。选择哪类模型取决于你的弹丸用什么物理：

### MC 原版模型（`MinecraftTrajectory`）

MC 原版弹射物（箭、雪球、火球等）使用**速度乘数阻力**——每 tick 的速度乘以一个固定系数（如 0.99），与弹丸质量、速度大小无关。特征：

- 阻力 = 速度 × 常数。质量不影响减速，速度大小不影响减速百分比。
- 相同 drag/gravity 组合在任何初速下弹道几何完全相同。
- 入参单位为 **m/tick**（与 `Entity.getDeltaMovement()` 一致），输出自动换算为 **m/s**。

```java
// 典型的 MC 原版弹射物正解
TrajectoryResult traj = MinecraftTrajectory.arrowTrajectory(
    new Vec3(0, 64, 0),           // 发射位置
    new Vec3(0, 0.5, 2),          // 初速矢量 m/tick
    100                            // 最大 tick 数
);
```

**适用场景**：

- 你的弹丸实体直接使用原版 MoveControl/Projectile 物理
- 箭、雪球、鸡蛋、药水、火球、三叉戟等原版弹射物
- 自定义弹射物使用了同样的速度乘数阻力模型

### 拟真模型（`RealisticTrajectory`）

拟真模型使用**二次空气阻力方程**——阻力与速度的平方成正比、与质量成反比、与截面积成正比。特征：

- 阻力 = ½·ρ·Cd·A·v²/m。质量越大减速越慢，速度越高阻力急剧增大。
- 弹道行为依赖速度——同一把枪初速翻倍，阻力变成四倍。
- 所有值使用**SI 单位**：速度 m/s，质量 kg，口径 m。
- 可从 `BFDamageExtensions` 的 `CALIBER` 和 `MASS` key 直接读取弹丸参数。

```java
// 典型的拟真弹丸正解——120mm 坦克炮 APFSDS
BallisticConfig config = BallisticConfig.fromExtensions(
    exts, 0.35f,    // Cd — 唯一需要手动指定的参数
    0.8f,           // MC 主世界重力 (m/s²)
    0.05f,          // 步长 = 1 tick
    200
);
TrajectoryResult traj = RealisticTrajectory.forwardSolve(
    start, new Vec3(0, 0, 1500),  // 初速 1500 m/s
    config, DensityFunction.MC_OVERWORLD
);
```

**适用场景**：

- 你的武器模组自定义了弹丸物理（非原版弹射物）
- 需要质量/口径影响弹道（重弹减速慢、细弹阻力小）
- 需要高空空气稀薄影响阻力
- 需要在不同维度使用不同的大气模型

### 快速选择指南

```
你的弹丸物理是什么？
├── 基于原版 Projectile/ThrowableProjectile 类
│     → 用 MinecraftTrajectory
│
├── 自定义物理，但你控制了阻力公式
│   ├── 阻力 = 速度 × 常数（速度乘数阻力）
│   │     → 用 MinecraftTrajectory（通用版传入自己的 dragH/dragV）
│   │
│   └── 阻力 = ½·ρ·Cd·A·v²/m（二次阻力）
│         → 用 RealisticTrajectory
│
└── 激光/近光速弹丸（速度极大，重力可忽略）
      → 两种理论上都可以，但拟真模型更合适（需要 Cd 传 0 走真空路径）
```

## 两者共用的接口

虽然 MC 原版和拟真模型底层物理公式完全不同，但它们输出的数据结构是**相同的**——`TrajectoryResult`、`FiringSolution`、`TrajectorySample` 在两个模型间通用。这意味着下游代码（弹道预览渲染、AI 瞄准、伤害上下文构造）不需要关心解算是哪个模型完成的。

另外两个模型都**自动识别退化路径**——当重力为零或阻力可忽略时，解算器自动跳过分步积分走 O(1) 解析路径。用户零配置即可享受性能优化。

## 单位约定

| 物理量 | MinecraftTrajectory 入参 | MinecraftTrajectory 输出 | RealisticTrajectory（全 SI） |
|--------|:---:|:---:|:---:|
| 位置 | m | m | m |
| 速度 | **m/tick** | **m/s** | m/s |
| 时间 | tick（内部） | s | s |
| 质量 | — | — | kg |
| 加速度 | m/tick² | — | m/s² |

MC 模型入参用 m/tick 是为了与 `Entity.getDeltaMovement()` 保持一致——你只需把弹丸实体的速度矢量直接传入，无需手动换算。输出自动转为 m/s（×20），确保与 `BFDamageContext.hitVelocity` 的单位一致。

拟真模型全链 SI——如果你习惯用公里/小时或英里/秒，请在外部自行换算后再传入。1200 m/s 约等于 4320 km/h，或马赫 3.5（海平面音速 ≈ 343 m/s）。MC 主世界的重力加速度约为 0.04 × 20 = 0.8 m/s²（真实世界 g ≈ 9.8 的约 1/12）。

## 文件位置

所有外弹道类位于 `io.github.sweetzonzi.ballistics_framework.api.trajectory` 包中。

| 类 | 类型 | 一句话职责 |
|---|------|----------|
| `TrajectorySample` | record | 单个采样点：时间、位置、速度 |
| `TrajectoryResult` | record | 正解结果：采样点列表 + 便捷查询 |
| `FiringSolution` | record | 反解结果：出射方向、飞行时间、末速、弹道类型 |
| `BallisticConfig` | record | 拟真参数组（Cd、质量、截面积、重力、步长） |
| `DensityFunction` | 函数式接口 | 空气密度按位置查询 |
| `MinecraftTrajectory` | 静态方法类 | MC 原版物理解算器 |
| `RealisticTrajectory` | 静态方法类 | 二次阻力拟真解算器 |

所有解算器方法均为 `static`、无内部状态、线程安全。服务器 AI 瞄准、客户端弹道预览、物理线程异步计算均可安全调用。

## 完整数据流

外弹道模块与终点弹道协议的衔接自然形成闭环：

```
BFDamageExtensions.MASS / CALIBER   ← 武器模组构造扩展数据时填入
        │
        ▼
BallisticConfig.fromExtensions()    ← 读取口径和质量，计算截面积
        │
        ▼
RealisticTrajectory.forwardSolve()  ← 外弹道解算
        │
        ▼
TrajectoryResult
  .terminalPoint()                  ← → BFDamageContext.hitPoint
  .terminalVelocity()               ← → BFDamageContext.hitVelocity（同为 m/s，直传）
  .approximateHitNormal()           ← → BFDamageContext.hitNormal（近似值）
        │
        ▼
BFDamageApi.hurt(target, ctx)       ← 进入终点弹道管线
```
