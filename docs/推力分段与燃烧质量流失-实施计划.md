# 推力分段与燃烧质量流失 — 实施计划

> **状态**：计划中（未实施）。当前实现是一次点火、恒力、恒质量的单窗口 `ThrustProfile(force, startSeconds, endSeconds)`，契约见 `docs/弹道求解器-推力项设计.md`。
>
> **定位**：本文拥有「分段推力与燃烧期质量」在 `RealisticTrajectory` / `ThrustProfile` 中的目标契约：API 形态、时间与原点的语义、每一处接线、验收断言与版本策略。单窗口形态的现有契约仍归 `docs/弹道求解器-推力项设计.md`，本文在落地后接管其第二节（API）、第三节（时间窗）、第六节（测试）以及第七、八节（误差边界与明确不做）。
>
> **本文自包含**：API 签名、质量公式、接线清单与验收断言都在文内给出，不要求先读其他文档。文中的行号对应当前 `1.21.1-neoforge` 分支。

## 一、目标与边界

| 能力 | 本计划 |
| --- | --- |
| **多次点火**：一条弹可以有多个燃烧窗口，窗口之间是纯弹道滑行 | 做 |
| **燃烧期质量流失**：推进剂在段内匀速烧掉，推力加速度随质量下降上升 | 做，按段可选、缺省关闭 |
| 推力曲线 / 推力随时间连续变化 | 不做 |
| 分级分离（级间分离、质量与迎风面积跳变） | 不做 |
| 推力方向（非沿速度）、攻角、侧向推力 | 不做 |
| 风、科氏力等其它外力 | 不做 |

两条理由决定了"做"的范围：

1. **段表是闭包**：单窗口是段表的一个元素，`NONE` 是空段表，因此分派门禁只需判"段表是否为空"这一条静态条件，不必引入按步分派。
2. **质量由段表唯一决定**：推进剂只随燃烧消耗，于是 `m(t)` 是段表的确定性函数，不需要新增运行期状态，也不需要把质量塞进 `BallisticConfig`（它是 record，加字段会破坏所有构造点）。

## 二、API

```java
public record ThrustProfile(List<Segment> segments) {

    /** 单个燃烧窗口；质量流失由 propellantMassKg 表达，0 = 本段恒质量 */
    public record Segment(float force, float startSeconds, float endSeconds, float propellantMassKg) {}

    public static final ThrustProfile NONE = new ThrustProfile(List.of());

    /** 单段、恒质量："一次助推"的规范写法，等价于一个 Segment、装药 0 */
    public static ThrustProfile of(float force, float startSeconds, float endSeconds);

    public boolean isActive();                 // 至少一段有效
    public float forceAt(float seconds);       // 段内 force，段外与空隙为 0
    public float startSeconds();               // 首段起点；NONE 为 0
    public float endSeconds();                 // 末段熄火时刻；NONE 为 0
    public float burnDuration();               // Σ 有效段时长
    public float massAt(float seconds, float launchMass);
    public ThrustProfile remainingSince(float elapsedSeconds);
}
```

两个入口，分工明确：

- **规范构造器** `new ThrustProfile(List<Segment>)` 是唯一能表达多段与装药的形式；
- **`of(force, startSeconds, endSeconds)`** 是"一次点火、恒质量"的规范写法，等价于 `new ThrustProfile(List.of(new Segment(force, startSeconds, endSeconds, 0f)))`。

只做一次助推的消费方（绝大多数使用场景）只需要 `of`，不必接触 `Segment` 与装药字段。三参**构造器**不提供，理由见 §六。

`force()` 不提供：多段剖面没有单一推力，保留它只会诱导调用方按单段写代码。调用点的 `thrust.force()` 一律改用 `thrust.forceAt(t)`。

## 三、语义

### 3.1 窗口与 `forceAt`

窗口 `[startSeconds, endSeconds)`，左闭右开，与 `RealisticTrajectory` 现有的步进判定一致：第 `i` 步覆盖 `[(i−1)Δt, iΔt)`，判定取步初时刻。段外与段间空隙返回 `0`。

段表在构造时按 `startSeconds` 升序排列，`forceAt` 线性扫描即可（段数是个位数量级）。

### 3.2 质量与 `massAt`

装药按段记录，段内匀速消耗：

```text
mdot_i        = propellantMassKg_i / (endSeconds_i − startSeconds_i)   （kg/s）
consumed_i(t) = clamp(t − startSeconds_i, 0, endSeconds_i − startSeconds_i) · mdot_i
m(t)          = max(launchMass − Σ consumed_i(t), ε)
```

- 排气速度 `ve_i = force_i / mdot_i` 是派生量，不是构造参数。
- `propellantMassKg = 0` 的段不消耗质量；整条剖面的装药为 0 时，`massAt` 必须逐位返回 `launchMass`——这是"旧行为逐位不变"的依据。
- `ε` 取一个远小于任何真实弹丸的质量（如 `1e-6 kg`），只用于避免除零；装药超过发射质量的剖面属于非法输入，由调用方（内容包加载）拒绝，库内不做业务校验。

### 3.3 规范化

构造器内完成四件事，调用方不必预处理：

1. 丢弃无效段：`force` 或段长为非正、任一值为非有限；
2. 按 `startSeconds` 升序排序；
3. 相邻段若有重叠，抛 `IllegalArgumentException`（允许空隙，空隙即滑行）；
4. 用 `List.copyOf` 冻结段表。`ThrustProfile` 会被三个线程并发读取（服务端积分、客户端外推、地形预载），值类型拿着一个可变列表就不再是值类型。

`startSeconds` 允许为负，沿用"负值表示从求解起点就已点火"的既有语义。

### 3.4 时间原点与 `remainingSince`

求解器的时间原点是**本次求解起点**（`t = 0` 为入参位置与速度对应的时刻）。段表的 `startSeconds` 与它同源。

中途重解（初速因命中改变、燃尽校核）时，调用方拿到的段表仍以**发射时刻**为原点，必须先平移到新的原点。`remainingSince(elapsed)` 做这件事：整体减去 `elapsed`、丢弃已燃尽的段、把正在燃烧的段裁剪为剩余时长，返回不可变的新剖面。它取代单窗口时代的换算口诀"传 `(force, 0, burnEnd − burnElapsed)`"。

注意 `remainingSince` 只裁剪时间窗，**不改装药**：裁剪后的段保留按剩余时长折算的推进剂，因此继续调用 `massAt` 时，`launchMass` 应传该时刻的实际质量而不是原始发射质量。这条由调用方负责，调用点需要一句注释说明。

## 四、`RealisticTrajectory` 接线

| 位置 | 当前写法 | 目标写法 |
| --- | --- | --- |
| `forwardSolve` 分派（L93） | `thrust.isActive()` | 不变；空隙由 `forceAt = 0` 自然跳过 |
| `thrustAppliedAtStep`（L219–222） | 比较 `startSeconds` / `endSeconds` | 删除；三个推力积分器改问 `thrust.forceAt(stepStart) > 0` |
| 三个积分器的 `aT`（L235、L262、L302） | 提到循环外除以 `config.mass()` | 移进循环，按步初时刻取 `forceAt` 与 `massAt` |
| `halfRhoRef`（L263、L303） | 含 `/config.mass()` | 移进循环，除数为该步的 `massAt` |
| `estimateSpeed`（L800–802） | `0.5 · aT · (end − start)` | 无装药：`0.5 · Σ (force_i/mass) · 段长_i`；有装药：`0.5 · ve · ln(m₀/m_f)` |
| 非推力路径的 `config.mass()`（L149、L186） | 常量 | 不动 |

三条不变式：

- **只要剖面含有效段，就走推力积分器**，包括段间空隙。于是非推力退化路径永远见不到变质量，它们可以继续用常量 `config.mass()`；代价是空隙步也走推力积分器，收益是分派门禁保持静态、不必按步分派。
- **单段剖面与单窗口等价**：`forceAt` 在窗口内返回同一个 `float`，`massAt` 在无装药时返回 `launchMass` 本身，因此 `aT`、除质量的算术与单窗口形态逐位一致。
- **`solveFiringAngle` 的门禁**（L412）仍用 `isActive()`，语义是"剖面里有推力"，与空隙无关。

## 五、测试

现有 `RealisticTrajectoryInvariantTest` 的 T1–T9 全部保留，5 处 `new ThrustProfile(...)` 改用 `ThrustProfile.of(...)`。新增：

| 编号 | 断言 |
| --- | --- |
| T10 | 单段 `of(f, s, e)` 与 T5 的参考解逐点一致 |
| T11 | 双段 + 空隙：空隙内的采样点与"只把第一段推到燃尽、然后无推力外推"的轨迹逐点一致；第二段起点之后速率按该段的冲量跃升 |
| T12 | 第二段起点晚于求解视界 ⇒ 与只含第一段的剖面逐位相同 |
| T13 | 重叠段在构造时抛 `IllegalArgumentException`；乱序段被排序后与顺序写入的剖面逐位相同 |
| T14 | 有装药时终速等于 `ve · ln(m₀/m_f)`（`ve = force / (propellantMass / 段长)`），相对误差 1e-3 |
| T15 | `propellantMassKg = 0` 时与不带该字段的剖面逐位相同（`massAt` 恒返回 `launchMass`） |
| T16 | `remainingSince(elapsed)` 从 `elapsed` 处续算，与不裁剪、从发射点一路算到同一时刻的尾部逐点相差 < 1e-3 m |

T14 与 T16 的容差口径与 T4、T5 一致：只捕获"项写错"这类米级偏差，不锁数值快照。

## 六、接口决策、版本与文档

- **不提供三参构造器**：不做 `ThrustProfile(float, float, float)`。它和规范构造器抢同一个 `new ThrustProfile(...)` 写法，还会让这个类型看起来像"三个字段的 record"，而它的状态是段表。同样的便利由 `of(...)` 承担，命名清楚、不会与构造重载混淆。`of` 不是兼容垫片，是常见形状的规范拼写：单段恒质量是绝大多数调用方的全部需求，也是本库最该短的那条路。
- **`NONE` 语义不变**：空段表 ⇒ 走与旧签名逐位一致的路径（T1 守住）。
- **版本**：`gradle.properties` 的 `mod_version` 升到 `1.0.0.alpha.15`；消费方（Machine-Max）同步改自己的 `ballistics_framework_version`。
- **文档同步**：落地时改写 `docs/弹道求解器-推力项设计.md` 的第二节（API）、第三节（时间窗）、第六节（测试编号）、第七节（质量流失从"若将来需要"改为已支持）、第八节（从"明确不做"中移出多段与质量流失）；本文的 `**状态**` 改为已实现；`AGENTS.md` 第 73 条的约定描述同步。

## 七、明确不做

- **推力曲线 / 任意函数**：固体发动机的实际剖面是"平台 + 尾段爬升"，2~4 个分段点足够；采样曲线没有消费方。
- **分级分离**：真正的多级有级间分离、质量跳变与迎风面积跳变。段表给的是"多次点火"，不含分离事件。
- **指令点火（飞行中由外部指令触发）**：它把 `startSeconds` 从常量变成每发实例的运行时状态，需要消费方自己持有"已解析的剖面"；库侧不引入该概念。
- **质量随时间的一般形式**：只支持"段内匀速消耗"。非匀速（如燃面变化）用更多分段近似表达。

## 八、与 Machine-Max 的衔接

| 内容包字段 | 折算到 `Segment` |
| --- | --- |
| `force` (N) | `force` |
| `start` (s，自发射瞬间) | `startSeconds` |
| `duration` (s) | `endSeconds = start + duration` |
| `propellant_mass` (kg) | `propellantMassKg`，缺省 0 |

- 内容包的 `external.thrust` 从对象改为段数组，`ignition_delay` 由 `start` 取代。
- Machine-Max 的积分器（`TrajectoryStep`）与求解器共用同一段表，时间原点同为发射瞬间，因此**不调用** `remainingSince`；调用它的是"求解起点晚于发射点"的消费方。
- 质量一律由 `massAt` 给出，`BallisticConfig#mass` 的语义是**发射质量**。消费方不得自己维护第二份质量曲线，否则两边会分家。
